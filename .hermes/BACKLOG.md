# AirTun — بکلاگ مشکلات و فیکسهای pending (ثبت شده 2026-08-26)

> لیست متمرکز تمام مسائل شناساییشده. ترتیب: اولویت کاربر.

## 🔴 P1 — باگها (تأییدشده توسط کاربر)

### ۱. حالت Web Proxy ویندوز وصل نمیشود (TUN سالم است)
- **علامت:** Connect در Proxy mode شکست میخورد؛ همان گوشی در TUN mode وصل میشود
- **محل احتمالی:** `windows/AirTun.Core/Proxy/ProxySession.cs` + `WinInetProxyStore.cs`
- **نکته دیباگ:** با port-fallback جدید پورت سرور ممکن است 10809 باشد — Proxy mode باید پورت صحیح را به WinINet بدهد. bypass list هم چک شود.

### ۲. تداخل پورت معکوس: AirTun اول روشن → v2rayNG بعداً خطا میدهد
- **سناریو:** AirTun بالا میآید 10808 را میگیرد → کاربر بعداً v2rayNG را روشن میکند → v2ray خطای bind میدهد
- **راهحل توافقی:** پورت پیشفرض AirTun از 10808 به رنج غیرمتعارف منتقل شود که هیچ فیلترشکن معروفی استفاده نمیکند
- **پیشنهاد:** 27510 (یا هر عدد 20000–30000)؛ fallback موجود حفظ شود
- **نکته:** پورت جدید باید در بیکون/UI/ویندوز همهجا از `server.actualPort` خوانده شود (زیرساخت آماده است)

## 🟡 P2 — UI/رفتار

### ۳. «Live Speed» در اندروید واقعاً speed نیست، حجم تجمعی است
- **محل:** `HomeScreen.kt:463` — `speedText = formatBytes(totalBytes) + "/s"`
- **مشکل:** totalBytes = bytesUp+bytesDown تجمعی؛ نمایش `/s` گمراهکننده
- **فیکس:** یا نام کارت به «Data Used / حجم مصرفی» تغییر کند، یا سرعت واقعی (delta بین دو sample) محاسبه شود — تصمیم با کاربر

### ۴. قطع ترافیک پس از خاموش شدن صفحه گوشی (WakeLock 10 دقیقهای)
- **محل:** `SharingService.kt:214` — `acquire(10 * 60 * 1000L)`
- **علت:** wake lock بعد از ۱۰ دقیقه آزاد میشود → Doze → کندی/قطعی
- **فیکس:** `acquire()` بدون timeout + release فقط در `teardown()` (سرویس foreground، نشتی ندارد)
- **تأیید کاربر:** هنوز نه — سوال شده
